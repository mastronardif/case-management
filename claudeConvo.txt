Yes — confirm both, with one important clarification.

1. ReceiverId / ReceiverQualifier

InsuranceCoverage.PayerId
        ↓
Payer.Id
        ↓
PayerEDI.PayerId
        ↓
PayerEDI.ReceiverId
PayerEDI.ReceiverQualifier

And we should not silently generate a blank ISA08/GS03/NM1*40 ID if the required receiver configuration is missing. I'd rather have the generator fail validation with something like:

PayerEDI receiver configuration is incomplete for PayerId 5:
ReceiverId and/or ReceiverQualifier is missing.

2. Payer.PayerCode / CodeQualifier

Yes. I agree: make PayerEDI the authoritative source and stop reading Payer.PayerCode / Payer.CodeQualifier.

I would leave the columns in the database for now, exactly as you suggested, and treat them as legacy:

Payer.PayerCode
Payer.CodeQualifier
        ↓
      LEGACY
      DO NOT READ

The new authoritative path is:

InsuranceCoverage.PayerId
        ↓
Payer.Id
        ↓
PayerEDI.PayerId
        ↓
PayerEDI.PayerIdentifier
PayerEDI.PayerIdentifierQualifier
PayerEDI.ReceiverId
PayerEDI.ReceiverQualifier

So yes — proceed with the rewire

I would make these changes:

Current	New
Get-Payer → payer code from Payer	Get-Payer → Get-PayerEDI
Payer.PayerCode	Stop reading
Payer.CodeQualifier	Stop reading

PayerEDI.ReceiverId	Authoritative receiver ID
PayerEDI.ReceiverQualifier	Authoritative receiver qualifier
InsuranceCoverage.PayerId	Still the starting point

One thing I'd add to the implementation: don't populate ISA08/GS03/NM1*40 from ReceiverName. The name and identifier are separate concepts. ReceiverName = Availity is descriptive; ReceiverId/ReceiverQualifier provide the actual identifier.
